# Specialist layer

This folder is the shared source for 12 role protocols, 10 deliverable routes, one shared finishing support skill and their channel rubrics. Native project entry points are generated by `scripts/sync_specialists.py`; `--check` detects drift without writing. The operator enters through `codex/launch-factory/SKILL.md`.

## Local fixture

From the repository root, with the existing Python dependencies installed:

```bash
.venv/bin/python engine/scripts/specialist_route.py route engine/fixtures/specialist-demo/request.json --workspace engine/fixtures/specialist-demo
.venv/bin/python scripts/sync_specialists.py --check
.venv/bin/pytest -q tests/test_specialist_routing.py
```

The fixture is fictional and tests routing only. Its route returns the selected skill, role bank, source/voice read set, actual draft text, exact review subject and named human reviewer. The helper makes no model or provider call. The operator must invoke the returned protocol to do the editorial work.

`request.schema.json` defines source hashes, exact character spans, voice selection, artifacts and direct dependencies. Use release-workspace-relative paths. Source and artifact IDs must be distinct. `registry.json` defines stage owners, channels and rubrics. A `render` request with missing capability evidence is held. Tool receipts remain operator-supplied evidence; the helper does not contact a provider to verify them.

`result.schema.json` accepts recommendations only. `validate-result` binds a review to the current product, campaign, asset version/hash and transitive input bindings. It checks rubric coverage and reference IDs. Semantic truth and visual quality require actual review.

`check-binding REQUEST.json --workspace PATH --result DECISION.json` compares a decision envelope's `subject` with the current subject. A changed script invalidates dependent media's binding; unrelated calendar changes do not. The comparison never authenticates or applies an event, including repeated events. A real human decision and any future trusted event store remain separate.

## Host status

The project files follow current [Codex custom subagent documentation](https://developers.openai.com/codex/multi-agent) and [Claude Code subagent documentation](https://code.claude.com/docs/en/sub-agents). Static parsing and entry-point checks do not prove host discovery or delegation. On a host without native roles, the operator reads the selected skill and bank and performs that protocol inline. Do not install a wrapper alone outside the full project tree.

## Maintainer boundaries

Do not translate a recommendation into `transition_slot.py --human-confirmed`. The legacy helper does not implement authenticated, ordered human decisions. This change does not repair that engine or supply the future app and n8n service. The historical Claude v0.2.0 ZIP remains a legacy skill-only archive and excludes this layer. Use the full repository project doors for the current layer.

Reference banks contain original reusable guidance. Private course sources, paid media and machine-specific product paths are not runtime dependencies. Optional carousel work requires explicit opt-in. All deliverables remain drafts until the actual human reviews their exact versions.

The stage-selected `lf-short-motion-finishing` skill belongs to the existing video lead and motion designer. Its `finishing/` folder contains an original ten-second cue example, typed speech Caption JSON, per-asset provenance/check schemas and an offline validator. Music-only edits skip speech generation and captions. User-approved duration belongs to the separate film brief; the social-video slot keeps its own cap.

The existing video lead also reaches [actor production](video-production/PROTOCOL.md). Its original prompt templates and `production-job/v1` record bind the accepted story/format, selected actor and voice references, exact speech, one sample, cost evidence and returned-media lineage. The checker performs local consistency checks only. Its fictional example starts held with recipient-owned accounts, pending approvals and unknown tool/quote evidence. The future n8n adapter still needs authenticated decisions and durable idempotency; no service is included.
