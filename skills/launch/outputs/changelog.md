# Changelog entry

## Reader

An admin who skims a list of changes and stops only when something affects their setup.

## Parts

Write these parts in this order, one line each unless noted.

1. Heading. The name of the change in a few words.
2. Status tag. Exactly one of beta, planned or released. Use released only when a source gives a release date. If no source gives one, use beta or planned and list the date question under "Not traced".
3. Summary. One line on what changed for the user.
4. Changes. Up to three short lines, each one visible change.

Put a source marker such as [1] after every claim in parts 2 to 4. The heading carries no marker.

## Length

4 to 6 lines in total. 8 to 60 words in total. Each change line is one sentence.

## Sources

Mark each claim in the text with [1], [2] and so on. After the entry, add a "Sources" list with one entry per marker. Each entry is the link the user gave, or "pasted text" when the user pasted it in. Every link the user gave appears in the list, or appears as "not used, because <reason>". Claims you could not trace to any source go under a "Not traced" heading after the list, and stay out of the entry text.
