# Social posts

## Reader

The audience the briefing names. If the briefing names none, write for a general user of the product and ask one question at the end of the turn: "Who is this for?" Whoever it is, they are scrolling a feed and give a post about two seconds, so each line must make sense on its own.

## Parts

Write three post options for the same change. Each option has these parts in this order, one line each.

1. Problem. The pain the reader knows. If no source names one, write "none in the sources".
2. Change. What is new, in plain words.
3. Proof. One number or example, labelled with where it comes from. If no source has one, write "none in the sources".
4. Status. Whether it is released, in beta or planned.

No link, no hashtags and no emoji in the post text. Any link the user gave goes in the Sources list only. Put a source marker such as [1] after the proof line and after any other claim. A "none in the sources" line carries no marker.

## Length

Each option is exactly 4 lines, and each option is 80 to 280 characters in total. Markers, the Sources list and the Not traced list are not counted.

## Sources

Mark each claim with [1], [2] and so on. After the three options, add one "Sources" list with an entry per marker. Each entry is the link the user gave, or "pasted text: <first five words>" when the user pasted it in. Every link the user gave appears in the list, or appears as "not used, because <reason>". Claims you could not trace to any source go under a "Not traced" heading after the list, and stay out of the posts. The text is handed back for a person to post by hand. Nothing is posted.
