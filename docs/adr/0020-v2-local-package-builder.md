# 0020: One local builder for v2

Status: implemented; human asset approval remains separate.

The old command copied adapter instructions into output folders and printed DONE. Its structural tests could not prove that a social video or popup existed. V2 replaces that path with `launch_factory.py`.

The AI host prepares source-grounded copy through the existing specialist protocols. A person locks claims. Python checks source spans and references, FFmpeg cuts footage and burns captions, and native HTML/CSS/SVG provide the remaining previews. Every build writes a new directory. Files and source records travel together.

This removes the legacy campaign/record state machine, instruction-copying package builder, placeholder fixtures, and two regenerated repository inventories. Git records source versions; built-package manifests record output versions. Specialist protocols and their tests stay because they still serve agent drafting and review.

No provider SDK, workflow framework, queue, database, or hosted approval system is required. Reconsider when multiple operators need authenticated approvals or queued remote renders. A local record is not identity proof. The bundled example rehearses the build without recording a human decision.

Publication, sending, and scheduling remain outside the tool. A rendering failure removes only the temporary work directory; existing packages are preserved.
